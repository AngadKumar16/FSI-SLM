================================================================================

CLI WORKFLOW (commands and what they do)
-----------------------------------------

  Generate dataset
    (cli.py generate-data -> Data/synthetic.py)
        -- emits synthetic RawExperiments -> artifacts/raw_data/experiments.jsonl

  Build SFT dataset
    (cli.py build-dataset -> Data/build_dataset.py)
        -- converts FeatureRecord + (optional) FAISS passages to JSONL
        -- artifacts/dataset/{train,val,test}.jsonl

  Index paper corpus
    (cli.py index-corpus -> rag/index.py)
        -- reads PDFs in Data/Papers/, encodes each chunk with MiniLM-L6-v2
        -- emits artifacts/rag_index/{index.faiss, metadata.json}

  Train adapter
    (cli.py train -> train/sft.py -> mlx_lm.lora.train_model)
        -- LoRA fine-tunes Phi-4-mini on the SFT JSONL
        -- emits artifacts/adapters/adapters.safetensors (46 MB)

  Evaluate
    (cli.py eval -> inference/runner.py + eval/evaluate.py)
        -- runs the trained adapter over the test split, scores against labels
        -- emits artifacts/eval_results/eval_results.json

  Run inference
    (cli.py infer -> inference/runner.py + mlx_lm.generate)
        -- produces structured interpretation for a single FeatureRecord

  Serve
    (cli.py serve -> serve/fastapi_app.py + inference/runner.py)
        -- exposes /infer /health /schema on an HTTP port

   Client / curl
        |
        v

        (serve/fastapi_app.py: create_app()'s /infer endpoint)
        |
        v

        (Pydantic InferRequest)
        |
        v
   InferenceRunner
        (inference/runner.py: lazy-loads model + adapter + FAISS)
        |
        +--- use_rag=False ----------------+
        |                                   |
        +--- use_rag=True ->                |
              Retrieve top-3 passages       |
                 (FAISS via rag/retrieve.py)|
                        |                  |
                        v                  v
                 Assemble RAG prompt        |
                    (rag/prompt_assembly.py)|
                        |                  |
                        v                  |
                 Build prompt              |
                    (render_chat + SYSTEM_PROMPT,
                     train/tokenization/prompt_template.py)
                        |
                        v
                 Generate text
                    (mlx_lm.generate, Phi-4-mini + LoRA)
                        |
                        v
                 Parse and validate
                    (eval/validate_output.py: parse_structured_fields)
                        |
                        v
                 JSON response
                    (InferResponse)

================================================================================

TRAINING LOOP (inside train/sft.py:train)
-----------------------------------------

   Configuration
        (TrainingConfig dataclass -- lr, iters, rank, alpha, etc.)
        |
        v
   Load base model
        (mlx_lm.utils.load)
        |
        v
   Inject LoRA
        (linear_to_lora_layers applied to all linear projections)
        |
        v
   Build ChatDataset
        (mlx_lm.tuner.datasets + mask_prompt=True so loss covers
         assistant tokens only, not the system/user prompt)
        |
        v
   Training loop
        (mlx_lm.tuner.train: cosine LR schedule, warmup,
         gradient checkpointing, clear_cache_threshold=1GB)
        |
        +-- every save_every iters ----> Checkpoint file
        |                                  (0000xxx_adapters.safetensors)
        |
        +-- at end ----> Final adapter
                          (artifacts/adapters/adapters.safetensors + adapter_config.json)

KEY DIRECTORIES AND THEIR ROLES
-------------------------------

  Data/                      -- "what is an FSI experiment" definitions
    schema.py                -- FeatureRecord / RawExperiment Pydantic models
    synthetic.py             -- simulator (5 flow regimes)
    describe.py              -- rule-based oracle (FeatureRecord -> text)
    build_dataset.py         -- SFT dataset builder with optional RAG aug
    Papers/                  -- input PDFs (gitignored)

  features/
    extract.py               -- raw experiment -> FeatureRecord feature extractor

  rag/
    corpus_loader.py         -- PDF chunk loader
    index.py                 -- FAISS index builder / loader
    retrieve.py              -- query, top-k retrieval, RetrievalResult dataclass
    prompt_assembly.py       -- assemble RAG context into the prompt

  train/
    tokenization/prompt_template.py
                            -- SYSTEM_PROMPT, render_chat, chat helpers
    sft.py                   -- TrainingConfig + train()
                                  (delegates to mlx_lm.lora.train_model)

  inference/
    runner.py                -- unified backend used by eval / infer / serve

  eval/
    validate_output.py       -- regex-based field extractor + validator
    evaluate.py              -- metrics: regime_macro_f1, lock_in_f1,
                                  avg_field_accuracy, per_field accuracy

  serve/
    fastapi_app.py           -- FastAPI app factory (/infer /health /schema)

  cli.py                    -- 7 subcommands via fire.Fire

  configs/default.yaml       -- hyperparameter registry

  artifacts/                 -- everything generated (gitignored)
    raw_data/                -- synthetic experiments
    dataset/                 -- SFT JSONL train/val/test
    rag_index/                -- FAISS index over Papers
    models/Phi-4-mini-.../   -- base language model snapshot (7.7 GB)
    adapters/                -- THE trained SLM (46 MB)
    eval_results/            -- JSON metric reports

NOTES
-----

  - "Base model loads once" means mlx_lm.utils.load is expensive (~30s).
    InferenceRunner caches the model so subsequent /infer calls take ~3s.
  - "RAG only retrieves, doesn't modify ground truth." The system prompt
    tells the LLM to ignore retrieved passages that conflict with the
    FeatureRecord's measured values.
  - "mask_prompt=True" means loss is computed only on the assistant
    response; tokens in system/user are ignored.
  - Path A (paper-grounded training, 25% RAG-augmented examples) trained
    but did not beat the no-RAG baseline; only the no-RAG adapter is
    retained at artifacts/adapters/.
