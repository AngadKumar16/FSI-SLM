ASCII mirror of docs/workflow.md. Boxes describe what each python file DOES;
the file name is in parens, so you can grep for either.

TWO HALVES, ONE CONTRACT
------------------------

  SURROGATE (sensor/)          "What does the flow do?"
      geometry + incidence  ->  fields, forces, deflection

  INTERPRETER (Data/, features/, train/, rag/, inference/)
      experiment record     ->  regime, lock-in, caveats

  The contract is FeatureRecord (Data/schema.py). The surrogate produces one,
  the interpreter consumes one. That is the ONLY coupling -- which is why a
  real PIV rig can replace the surrogate without touching anything downstream.
  Substitution point: sensor/bridge.py:build_raw_experiment

  `cli.py twin` runs both halves back to back = the full digital twin.

WHY THREE SOLVERS (this is a measurement, not a preference)
-----------------------------------------------------------

  alpha <= 8 deg   -> steady RANS converges to 1e-5, ~100x cheaper than transient
  alpha >= 10 deg  -> URANS is the only one that HAS an answer

  Every steady case at alpha >= 10 hit the 2,000-iteration cap with initial
  residuals of order 1e-2 and lift oscillating by up to +/-0.43. Massively
  separated flow has no steady solution to converge TO -- simpleFoam
  limit-cycles, and whichever iteration it stops on is an arbitrary point on
  the oscillation. Convergence is recorded per case; --converged-only drops
  the rest.

  finalize_manifest ranks urans > rans > panel for the same (foil, angle),
  so re-solving a case upgrades it in place.

THE 13-CHANNEL INPUT CONTRACT (sensor/sdf.py, InputSpec "v2")
--------------------------------------------------------------

   sdf                 signed distance, chord units
   x, y                grid coordinates (flow is NOT translation-invariant)
   n_x, n_y            grad(sdf) = wall normal
   wall                exp(-d/0.05c), near-wall emphasis + scalar-head weight
   pot_u, pot_v, pot_p INVISCID PRIOR -- panel solution on the same raster
   fs_x, fs_y          freestream direction     ) read back as a global
   log_re              Reynolds conditioning    ) vector and injected
   fidelity            panel / rans / urans     ) via FiLM, not as maps

  The prior is the change that matters most: with pot_* present the network
  predicts the CORRECTION to potential flow, not the flow. Stagnation point,
  circulation, suction-peak location and the far field arrive already exact.
  Costs one panel solve (~40 ms) per case at cache time, and is available at
  every fidelity -- so a RANS row gets the same prior and the two stay
  interchangeable.

  Ablate it:  python cli.py sensor-cache --spec v2_noprior

TWIN BRIDGE DETAIL (sensor/bridge.py: steady fields -> experiment record)
--------------------------------------------------------------------------

  wake width          <- half-deficit points 1.5 chords downstream
  separation point    <- first chord station where near-wall flow reverses
  Den Hartog margin   <- dCl/dalpha + Cd < 0  (two extra solver calls)
  shedding frequency  <- MEASURED from the URANS lift signal when the case
                         has one (lookup_unsteady in the manifest);
                         otherwise Roshko St on the Fage-Johansen projected
                         height c(sin|alpha| + t/c).
                         provenance.shedding_frequency says WHICH.
  structural amplitude<- SDOF transfer function at r = f_shed / f_n
  regime              <- by rule: attached/separated by separation point,
                         lock-in by frequency ratio, galloping by Den Hartog,
                         stall flutter by proximity to the stall break

  The match in lookup_unsteady is on the .dat stem ("n0012"), NOT the title
  inside the file ("NACA 0012") -- those differ. Angle must agree to a
  quarter degree, because shedding frequency varies with incidence and a
  nearby case is a different measurement.

  THE TIME SERIES ARE A MODEL OF THE INSTRUMENT, NOT A MEASUREMENT.
  Every record says so in notes and provenance.

CLI WORKFLOW (21 commands; `python cli.py -- --help` lists them)
-----------------------------------------------------------------

  SURROGATE
    sensor-generate      107 sections x 18 angles = 1,926 cases, ~2 min/4 cores
    sensor-rans          steady OpenFOAM sweep; below stall only
    sensor-urans         unsteady sweep: time-averaged fields + measured f_shed
    sensor-multifidelity plan (--run) high-fidelity coverage of TRAINING foils
    sensor-finalize      merge sweep chunks into manifest, highest fidelity wins
    sensor-cache         flatten to 13-channel memmaps (--spec picks contract)
    sensor-preflight     time real steps, project the cost of the full run
    sensor-train         train the U-Net
    sensor-eval          score on held-out sections (--fidelity, --tta)
    sensor-predict       coefficients + fields for one section and incidence

  INTERPRETER
    generate-data        synthetic RawExperiments -> artifacts/raw_data/
    build-dataset        FeatureRecord + oracle -> {train,val,test}.jsonl
    index-corpus         PDFs -> artifacts/rag_index/{index.faiss,metadata.json}
    train                MLX LoRA fine-tune of Phi-4-mini
    eval                 score the test split -> eval_results.{json,md}
    infer                interpret a single FeatureRecord

  BOTH / SURFACES
    twin                 geometry -> fields -> record -> quality -> interpretation
    serve                FastAPI on an HTTP port
    ui                   Gradio web UI
    mcp                  MCP server over stdio
    demo                 end-to-end terminal demo, no model, runs in seconds

NOTES
-----

  - Base model loads once. mlx_lm.utils.load is ~30 s; InferenceRunner caches
    it so subsequent /infer calls take ~3 s.
  - RAG only retrieves, it does not modify ground truth. The system prompt
    tells the model to ignore retrieved passages that conflict with the
    FeatureRecord's measured values.
  - mask_prompt=True means loss covers assistant tokens only; the model is
    never scored on reproducing the record it was handed.
  - The ground-truth regime is excluded from to_prompt_block(), so the model
    must infer it rather than copy it.
  - Two serve paths, two DIFFERENT models: the LoRA adapter does the fixed
    6-part interpretation; open-ended questions go to the BASE instruct model
    with the record pinned into context.
  - Path A (paper-grounded training, 25% RAG-augmented examples) trained but
    did not beat the no-RAG baseline; only the no-RAG adapter is retained.
  - Interactive zsh does not treat '#' as a comment, so a trailing note on a
    cli.py command arrives as positional arguments. cli.py detects and rejects
    that rather than binding it to a parameter. Note also --alphas="-8,...":
    a bare leading minus is parsed as a flag.
